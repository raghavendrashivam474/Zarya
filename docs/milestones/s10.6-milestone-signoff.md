## 2. Definitive S11 Recommendations

Based on the empirical evidence gathered during the S10.6 evaluation:

### A. Sub-Step Granular Progress (GAP-01)
*Finding:* For multi-step work plans, keeping the UI locked in WORKING without sub-step progress indicators for sequences longer than 5 seconds creates a perceived freeze.  
*Decision:* **Partially Approve for S11.** We recommend exposing lightweight backend execution step triggers (work_step_started, work_step_completed) to the WebSocket without rewriting the core Python execution boundaries or shifting to asynchronous streaming protocols.

### B. Recovery Loop Visibility (GAP-02)
*Finding:* Users care about outcomes, not self-healing operations. Exposing internal recoveries can induce user anxiety.  
*Decision:* **Permanently Defer.** Recovery loops should remain completely internal to the Python agent boundary (gent/recovery.py).

### C. Refined 'UNKNOWN' Mapping (GAP-04)
*Finding:* The internal UNKNOWN state maps to an "uncertainty" expression, which lacks clear communication context for the user.  
*Decision:* **Approve for S11.** The frontend should map internal UNKNOWN semantics to a friendly non-celebratory label (*"Action completed; self-verification is not supported for this tool"*), preserving the strict S10 epistemic safety rules.
