## 8. Presence Architecture Note

The existing `avatarStyle: "character" | "orb"` in `ElysiaSettings` (settingsStore.ts:31) already provides a presence abstraction:

- `"orb"` → abstract orb visualization (current default)
- `"character"` → video-based character presence (idle.webm, talking.webm, thinking.webm already exist in public/assets/)

This means the presence boundary **already exists**. S10.3 should:
1. Rename the visualizer component
2. Document the existing modes
3. NOT introduce a redundant abstraction layer

The `public/assets/` directory already contains:
- `idle.webm` (140KB)
- `talking.webm` (153KB)
- `thinking.webm` (140KB)
- `orb2.gif` (17MB — orb fallback)
- `download.gif` / `download_static.png` (setup visuals)

These `.webm` files suggest the "character" mode was already partially implemented.
