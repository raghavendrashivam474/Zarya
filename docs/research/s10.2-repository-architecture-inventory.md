## 2. Invariants & Preservation Contracts

### 2.1 The Python Runtime Boundary
The Python engine in `agent/` remains strictly untouched. The bootstrapper `run_agent.py` will be relocated to `scripts/run_agent.py` but must always be executed from the repository root directory (where `agent/` lives as a standard module).

### 2.2 The Runtime State Boundary (`memories.json`, `settings.json`)
These files are gitignored local state files. Their default storage resolution must be updated in `server/paths.ts` to output inside a root `data/` folder (or system fallback) instead of cluttering the working directory root.

### 2.3 The Launchers Boundary
To prevent user confusion, thin launcher scripts will be written at the root (or existing root launchers will delegate to `scripts/`) to preserve the dead-simple `./start_zarya.sh` interface.

### 2.4 TypeScript Import Integrity
Since backend imports are completely local/relative (`./server_memory`), grouping all 4 modules together into `server/` minimizes risk.
