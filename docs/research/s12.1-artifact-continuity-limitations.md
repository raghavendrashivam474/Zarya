# S12.1 Limitations: Artifact Continuity Hardening

## Current Scope & Intentional Boundaries

1. **Single Active Target per Type**:
   - The current context maintains one primary `_active_artifact` and one `_active_application`. Multi-document concurrent work environments (e.g., side-by-side editing across 5 files) resolve "it" to the most recently touched artifact. Multi-target disambiguation across complex workspaces will be addressed in future context enhancements.
2. **Ephemeral In-Memory Lifecycle**:
   - Active computer context lives for the duration of the process / session. Long-term historical provenance across restarts is the domain of S7 `MemoryStore`.
3. **GUI Window Tracking**:
   - Application launching validates process spawn and arguments. Deep UI tree inspection and window handle state are out of scope for S12.1.
4. **External Out-of-Band Modifications**:
   - If an external process modifies or moves a file outside Zarya's tool execution envelope, Zarya's active context will not detect the change until the next tool operation touches that file.
