# S10.3 — Frontend Presence Investigation

**Date:** 2025-07-11
**Milestone:** S10.3
**Component:** Frontend Identity & Shefali Presence

---

## 1. Context & Motivation

Before S10.3, the frontend contained remnants of the ELYSIA-era UI where system work and visual presence were conflated. The visualizer was titled `ElysiaCoreVisualizer` and the system state indicators directly reflected legacy naming.

S10.3 investigated the existing presence architecture to cleanly decouple:
- **Zarya:** The underlying computer-work runtime, tool dispatch engine, and verification fabric.
- **Shefali:** The human-facing companion persona, conversational voice, and visual expression interface.

---

## 2. Investigation Findings

### 2.1 Existing Presence Capabilities
The codebase already contained a foundational presence mode abstraction in `ZaryaSettings` (`avatarStyle: "character" | "orb"`):
1. **`orb` mode:** Canvas-based energetic ring / orb visualizer using dynamic SVG geometry and `orb2.gif`.
2. **`character` mode:** Video-based digital human loop using three pre-rendered `.webm` streams located in `public/assets/`:
   - `idle.webm` — Attentive resting state.
   - `talking.webm` — Vocal expression stream.
   - `thinking.webm` — Cognitive / reasoning state.

### 2.2 Epistemic Decoupling
The presence visualizer previously responded directly to voice stream states (`disconnected`, `connecting`, `listening`, `speaking`).

To preserve S0–S10 epistemic integrity:
- Shefali's expression controller must strictly consume verified runtime states (`VERIFIED_SUCCESS`, `VERIFIED_FAILURE`, `UNKNOWN`, `BLOCKED`).
- Shefali must never present speculative celebration or success on unverified operations.

---

## 3. Architecture Alignment

The component was refactored into:
- `src/components/ShefaliPresence.tsx` (the active visual rendering component)
- `src/components/presence/ShefaliPresenceController.ts` (the state translation boundary)
- `assets/shefali/IDENTITY.md` (the visual specification)

Future realistic digital human presence levels (e.g. 3D canvas, live neural lip-sync) can plug into `ShefaliPresenceController` without touching Zarya's backend contracts or verification fabric.
