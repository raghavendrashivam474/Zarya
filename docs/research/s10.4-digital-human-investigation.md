- onStateChange → liveState
- onToolCall → setCharacterState("thinking")
- turnComplete → setCharacterState("idle")
- audio playback → setCharacterState("talking")
     ↓
   characterState: "idle" | "thinking" | "talking"
     ↓
   ShefaliPresence → video crossfade


**Critical Gap:** `PRESENCE_EXPRESSION_MAP` defines 10 `RuntimePresenceState`
values but only 3 are wired to actual visuals. The richer states
(VERIFYING, VERIFIED_SUCCESS, VERIFIED_FAILURE, UNKNOWN, BLOCKED) are
defined in the controller but never consumed by the component.

**Zero new dependencies. Zero runtime file changes. Zero architectural refactors.**

## Trust Preservation

The `deriveRuntimeState()` function maps only from signals the frontend
actually receives. Since the backend does not currently send explicit
VERIFIED_SUCCESS / VERIFIED_FAILURE messages, the frontend will default
to UNKNOWN after tool completion — never inferring success from HTTP 200
or tool dispatch. This preserves the S1–S10 trust model.
