# S10.4 — Digital Human Limitations & Next Steps

## Milestone Scope Recap
S10.4 established the minimal credible digital-human representation of Shefali integrated with Zarya's runtime state flow without modifying the underlying Python execution engine or adding heavy graphics frameworks.

## Current Limitations

1. **Pre-rendered Loop State Machine:**
   - Shefali currently transitions between pre-rendered high-definition video loops (`idle.webm`, `thinking.webm`, `talking.webm`) augmented with dynamic Framer Motion overlay shaders.
   - Real-time 3D facial rigging, blendshapes, and viseme-level morph targets are not yet implemented.

2. **Audio-Driven Visualizer vs. Real-Time Lip-Sync:**
   - Speech presentation is driven by the 24kHz Web Audio `outputAnalyser` frequency energy and loop crossfade rather than real-time phoneme-to-viseme neural mapping.

3. **Conservative State Mapping:**
   - Because the existing WebSocket protocol between `server/index.ts` and the frontend transmits tool calls and audio turns but lacks an explicit `VERIFIED_SUCCESS` / `VERIFIED_FAILURE` verification frame, the frontend conservatively maps tool execution to `WORKING` and tool completion to `UNKNOWN` or `LISTENING`.
   - Explicit verified state propagation over WebSocket is slated for protocol extensions in future milestones.

4. **Static Camera & Lighting:**
   - Shefali is currently positioned in a fixed holographic stage perspective. Real-time dynamic scene relighting and head tracking across full 3D space are future milestones.

## Recommended Next Steps for Future Milestones
- **S10.5 / S11:** WebSocket protocol enhancement to stream verified outcome tokens (`VERIFIED_SUCCESS`, `VERIFIED_FAILURE`, `OBSERVATION_DIFF`) to frontend.
- **Future:** Lightweight WebGL / Three.js / WebGPU Shefali mesh renderer with morph targets for zero-latency lip sync.
