# S12.1 Research: Artifact Continuity Hardening

## 1. Context & Review Findings
During senior review of Milestone S12 ("Artifact Identity & Computer Context Continuity"), several hardening targets were identified:
1. **Verification Semantics Drift**: S12 inadvertently forced `unverified_ok=True` across observation tools (`readFile`, `listFiles`, `searchFiles`, `systemInfo`, `takeScreenshot`) inside `agent/intent.py`. This relaxed S6 strict epistemic guarantees where unverified tools must result in `UNKNOWN` unless explicitly authorized.
2. **Fragile Creation Heuristic**: Artifact establishment relied on `"create" in artifact.source_operation.lower()`, which was brittle and unmaintainable.
3. **Active Context Scoping**: `ActiveComputerContext` lacked explicit lifecycle reset semantics and scoped context injection in multi-step execution.
4. **Mutation Continuity**: Renaming (`renameFile`) or moving (`moveFile`) a tracked file did not preserve the logical artifact identity, resulting in orphaned artifacts.
5. **Desktop Live Validation**: Real-world end-to-end Windows execution (`CREATE -> OPEN -> EDIT -> READ -> VERIFY`) required verification against the live OS environment.

## 2. Architectural Decisions & Fixes
- **Restoration of S6 Continuation Semantics**: Removed hardcoded tool checks from `S8WorkPlan.to_s6_plan()`. `S8Step` now defaults to `unverified_ok=False`. Unverified tools correctly yield `UNKNOWN` unless explicitly designated.
- **Explicit Operation Categories**: Defined immutable operation category sets (`ARTIFACT_CREATING_OPERATIONS`, `ARTIFACT_MUTATING_OPERATIONS`, `ARTIFACT_READING_OPERATIONS`). Replaced string heuristics with direct category membership.
- **Identity Preservation Across Rename & Move**: When `renameFile` or `moveFile` succeeds, the existing `ArtifactIdentity` is updated in-place (updating `canonical_locator`, `display_name`, `last_verified_at`, and `metadata["previous_locators"]`), preserving continuity.
- **Scoped Context Lifecycle**: Added `reset()` to `ActiveComputerContext` and added optional `context` parameter injection to `execute_work` and `_interpolate_step_args`.
- **Live Desktop Smoke**: Validated live notepad execution and filesystem ground truth via `scripts/smoke_s12_1_desktop.py`.

## 3. Epistemic Safety Verification
All S2/S3/S4/S5/S6/S7 invariants remain strictly preserved:
- `Action != Verification != Outcome`.
- `VERIFIED_FAILURE` and unverified `UNKNOWN` never establish active verified artifacts.
- Target ambiguity produces `AMBIGUOUS` / `NOT_FOUND` clarification requests rather than guessing.
